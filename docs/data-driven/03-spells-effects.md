# Stage 3 - spells, status effects, missiles, damage types

Prerequisites: stages 1 and 2 (tags, `race.units`, unit records). Overview: `README.md`.

## 3.1 Where the code stands

`spells.lua` (1085 lines) holds:

- data: `COST[0..129]`, `DURATION` classes, `SPHERE_NAMES`, name / description from `Spells.txt` (by number);
- helpers private to the file: `newCtx`, `each` (area targeting, 24 targets, sorted row by row), `nearestEnemies`,
  `ring` / `bolt` (visual effects pushed into `w.effects`), `hurt`, `heal`, `buff`, `buffGroup`, `debuffEnemies`,
  `summon`, `corpses`, `giveItem`, `sideTimer`, `hitMany`, `areaHurt`, `revive`, `replace`, `place`;
- `D[id] = { ai = "heal"|"attack"|"summon"|"buff", target = "ground"|"enemy"|"ally", portal = code, fn = function(c) }`
  with 130 closures that read `c.lvl` (success level), `c.r` / `c.rm` (radius), `c.empPct`, `c.ext` (duration
  multiplier) and call the helpers;
- the cast machinery: `castSkill`, `castLevel`, `chance`, `roll`, `cost`, `canCast`, `cast`, `perform`, `unitCast`
  (troops casting ability buttons reuse hero spell `fn`s), `ai` use.

`status.lua` keeps timed effects as `u.fx[kind] = { t1, value, ... }` with the kinds listed in its header; what each
kind *does* is spread over `status.update`, `unit.lua` (damage, move, attack) and `hero.lua`. Missiles and damage
types are numbers and strings in `unit.lua`, `items.lua`, `hud.lua`.

## 3.2 Target model

```lua
content.sphere:add{ id = "healing", slot = 0, name = textref, colour = {..}, castSkill = 10 }   -- skill id 10 + slot

content.spell:add{
  id = "healing.minor",       -- original: "<sphere>.<name>" ids generated by the importer; slot = 0..129 = sphere*10 + index
  slot = 0, sphere = "healing", index = 0,
  name = textref, desc = textref,            -- original: Spells.txt by number; mods give their own text
  cost = 8,                                  -- COST[slot]
  target = "none"|"ground"|"enemy"|"ally"|"unit",
  ai = "heal"|"attack"|"summon"|"buff"|{ use = fn(ai, hero, spell) },
  duration = "normal",                       -- a key of content.setting "spell.duration" or { base, step }
  portal = "BPxx"|nil,                       -- building id of the summoning portal / circle bonus
  icon = iconref, sound = soundref, effectSprite = spriteRef,
  pictures = { cast = "EZ11", target = "EZ11", persistent = "EBLS", base = false },  -- effect pictures of a cast (implemented)
  effect = <recipe> | fn(ctx),               -- see 3.3
}
```

- **Spell slots**: `COUNT = 130` becomes `#content.spell:all()`; "sphere * 10 + index" stays the slot of original spells
  (heroes, saves and profile data store slots). New spells get a slot from `slots.lua` (`spell` namespace) at the first
  free index `>= 130`; spheres may be larger than 10 spells (`sphere.size`), the spell book pages by sphere.
- **Hero casting skills**: `castSkill(h, sphere)` reads `h.skill[10 + slot]`; with data-driven spheres the skill id
  is `sphere.skill` (stage 4 `skill` records), so a new sphere ships its skill.
- `Spells.txt` names stay string references (`orig:Spells.txt#SPELL_NAME_<slot>`); `spells.name(id)` resolves them.

## 3.3 Effects: declarative recipes first, functions second

Observation from the 130 closures: most are one to five calls to the same helpers. Plan: (a) export the helpers as the
public **effect library** `fx`, (b) express the common shapes as **recipes** (tables of primitives that the engine
interprets), (c) allow a spell `effect = function(ctx)` for the rest, written against `fx`.

### The `ctx` object (read-only inputs)

`ctx.caster`, `ctx.hero`, `ctx.side`, `ctx.world` (opaque; queries only through `fx`), `ctx.target`, `ctx.level` (success
level 1..), `ctx.radius` (`c.r`), `ctx.radiusMastery` (`c.rm`), `ctx.empower(n)` (applies the side's Empower), `ctx.ext`
(duration multiplier), `ctx.portal`, `ctx.rng(n)` (deterministic die, **the only random source a mod may use**; it is
the simulation's seeded stream, so lockstep stays in sync), `ctx.time`.

### The `fx` primitive library (the old local helpers, renamed and documented)

| group | primitives |
|---|---|
| targeting | `fx.each{ who="enemy"|"ally"|"other"|"any", radius, from, max=24, filter=fn }`, `fx.nearest(ctx, n, radius)`, `fx.corpses(ctx, radius)` |
| damage / heal | `fx.hurt(target, amount, damageType)`, `fx.heal(target, amount)`, `fx.areaHurt{...}`, `fx.hitMany{...}`, `fx.cure(unit)` |
| status | `fx.status(target, statusId, seconds, value, extra)`, `fx.statusGroup{...}`, `fx.sideTimer(key, seconds)`, `fx.clearStatus(unit, negativeOnly)` |
| creation | `fx.summon{ unit, count, seconds, near, illusion }`, `fx.place{ building, seconds }`, `fx.replace(unit, newUnit, side)`, `fx.revive(unit, fraction)` |
| economy / items | `fx.give(resourceTable)`, `fx.giveItem(tier)`, `fx.dropItem` |
| visuals | `fx.ring{...}`, `fx.bolt{...}`, `fx.sound(id)`, `fx.sprite{...}` (data, deterministic: no wall clock, no `math.random`) |
| queries | `fx.isTag(unit, tag)`, `fx.distance(a, b)`, `fx.side(ctx)` fields: `enemies(a,b)`, `isAlly(a,b)` |

All primitives are thin wrappers over today's local functions; their semantics (24-target cap, row-major order,
"hero resistances apply to magic damage") are preserved bit for bit - that is the whole point of moving them unchanged.

### Recipes

A recipe is an array of steps; the interpreter lives in `content/recipes.lua`:

```lua
effect = { aura = "heal", radius = 2,
           { heal = { target = "self", amount = { base = 50, perLevel = 50 }, empower = true } } }

effect = { { each = { who = "ally", radius = "r" },
             do_ = { { cure = true }, { heal = { amount = { perLevel = 10 }, empower = true } } } },
           aura = "heal" }

effect = { { status = { id = "morale", who = "self", seconds = { duration = "normal" }, value = { base = 1, perLevel = 1 } } },
           aura = "light", auraRadius = 2 }
```

Amounts are `n | { base, perLevel, perLevelSq }`; durations `{ duration = "<class>" }`; radii `"r" | "rm" | n`.
The importer-side "base" layer ports the original spells **one sphere at a time**: a spell is rewritten as a recipe only
if the golden test (3.6) gives identical results, otherwise it stays `effect = function(ctx)` using `fx`. No spell may
change behaviour in this stage.

## 3.4 Status effects

```lua
content.status:add{
  id = "poison",
  kind = "state"|"stat",               -- stat statuses add `value` to a statistic (STAT table)
  stat = "combat",                     -- for kind = stat
  negative = true,                     -- status.NEGATIVE
  icon = iconref,                      -- unit.lua STATUS_ICONS
  exclusive = { "disease" },           -- poison and disease exclude each other
  duration = ms | { class = "poison" },
  stacking = "refresh_keep_stronger"|"replace"|"add",
  on = {                               -- hooks, all optional, all deterministic
     apply = fn(unit, fx), remove = fn(unit),
     tick = { every = 1000, fn = fn(unit, fx) },       -- poison 1 hp / s, immolation, ...
     stats = fn(unit, stats) -> stats,                -- status.stats
     damage = fn(unit, dmgType, ranged, dmg) -> dmg,  -- status.reduce (ward, resfire, resmagic ...)
     canAct = fn(unit) -> bool,                       -- stun, fear
  },
}
```

Work: `status.lua` becomes the **engine** (apply / refresh / tick / expire) and the 25 original kinds move to
`content/base/statuses.lua`; `unit.lua`'s per-kind branches (`u.fx.stun`, `u.fx.slow`, `u.fx.invis` ...) call the
hooks, with direct field access (`u.fx.stun`) kept as the fast path for kinds flagged `engine = true`
(`stun`, `slow`, `ward`, `invis`, `poison`) - extending that list is a core change, not a mod operation. Save
format: `fx` is stored as-is; unknown kinds from a missing mod are dropped with a warning.

## 3.5 Damage types, missiles, psychic effects

- `damagetype` records: `slashing, crushing, piercing, fire, ice(cold), electricity, magic` with `slot` 0..6, name
  (`strings`), icon (`BM_DAMAGEICONS` frame), colour, `armourStat`, `resistanceStat`, `isElement`. Replaces the numeric
  types and the three string tables (`unit.ELEMENT`, `items.DAMAGE_TYPES / ELEMENT`, `spells.COL`/`hurt`'s
  `{ "fire", "ice", "electricity", "magic" }`).
- `missile` records keyed by code (`EMA0` ...): sprite, speed, arc, sound pair (`MISSILE_SOUND`), `onHit` hook,
  `resistedBy` tag list (`powerups.RESISTANT_MISSILE`), `petrify` etc. (`EMM5`). Units reference a missile by id
  (they do today by code in `Army.cfg`).
- `psych` effects (fear / awe / conversion strength): `psych` kind records, icons from `hud.PSYCH_ICONS`.
- Critical-hit specials (`HIT` table, freeze / stun / cleave / drain in `unit.lua`'s `strike`) move into a
  `hitspecial` kind keyed by damage type with the same hooks as a status, so a mod can add "crushing stuns for 5 s".

## 3.6 Verification

The spells are the riskiest move. Golden test `tools/spelltest.lua`:

1. A seeded world with 8 units per side and a hero per spell; for each of the 130 spells at each success level 1-4
   (with and without Empower / Extend side buffs) record: mana spent, cooldown, per-unit hp / status table / position
   deltas, buildings placed, resources given, number of `w.effects` entries. Serialise to
   `tests/golden/spells.txt` **generated locally** (it is derived from running the engine, it contains no original
   data beyond ids, but keep it out of the repo if it reproduces unit stats; the repo carries only the hash per spell).
2. Run before and after each sphere's migration. Hash per spell must match exactly.
3. `--selftest --sim all` AI runs compare (hero spell usage depends on `ai =` tags).

## 3.7 Task list

1. Export the helpers as `fx` + `ctx` objects (no behaviour change). `spells.lua` locals become `fx.*` aliases.
2. Create kinds `sphere`, `spell`, `damagetype`, `missile`, `status`, `psych`, `hitspecial`.
3. Move `COST`, `DURATION`, `SPHERE_NAMES`, `COL` into base records; `M.cost / castSkill / castLevel / chance / roll` read
   the records (formulas stay in code; **cost modifiers (Mana Flow)**, the chance rule and the duration rule are
   `setting` entries / hook points so total-conversion mods can replace them).
4. Port spells sphere by sphere (13 spheres): recipe where identical, `effect = function(ctx)` otherwise; delete `D`.
5. Port `status.lua` kinds; unit hooks.
6. Port damage types and missiles; update `items`, `hud`, `unit`.
7. Spell book, spell bar, AI casting (`ai = ...`), hero profile and savegame refer to slots / ids; `spellbook.lua`
   pages by sphere with dynamic size; `spellbar` colours from `sphere.colour`.
8. Troop abilities that reuse hero spell functions (`armyabilities.lua` ABILITIES: `spell = id`) refer by spell id.

## 3.8 Acceptance

- A mod adds a sphere "Chronomancy" with two spells (one recipe, one function), they appear in the book of a class
  that lists the sphere skill, cast, save, load, and replay over lockstep without desync.
- A mod retunes Fireball (radius, damage) with a one-line patch; a mod removes `Resurrection`; heroes that know
  it lose it with a log line.
- Spell golden hashes unchanged for the 130 original spells; the old `spells.D` table no longer exists.
